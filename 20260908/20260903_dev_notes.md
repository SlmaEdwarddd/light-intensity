## 一、做過的實驗與變更(時序)

### 階段 0 — 程式追蹤與量測完整性修正

先追蹤整支程式的資料流:

```
相機執行緒 → current_frame → 分析執行緒(每個 ROI 取樣、平均)→ 每秒一筆 → CSV
```

發現並修正 6 個「不會報錯、但會默默污染數據或卡死」的問題:

| # | 問題 | 修正 |
|---|------|------|
| 1 | FPS 限流只留每秒「前 N 幀」→ 對市電紋波(100/120 Hz)相位混疊 | 改用 `time.monotonic()` deadline,保留幀平均分佈於整秒 |
| 2 | 分析迴圈沒跟幀同步,同一幀被重複計入不定次數 | 新增 `frame_seq` 序號閘門,每幀剛好計入一次 |
| 3 | 分析執行緒直接呼叫 Tk(繪圖/log)→ Tcl 非執行緒安全 | 改用 `root.after(0, …)` 丟回主執行緒 |
| 4 | 執行中存檔遇欄位比索引長一格 → 靜默失敗(打包 exe 無 console) | `save_csv` 開頭一次性快照並截齊長度 |
| 5 | 相機讀取例外 `except: continue` → 斷線變 100% CPU 熱迴圈 | 計數退避,連續失敗約 1 秒才提示 |
| 6 | resize 失敗塞入原始解析度幀 → 座標與 ROI 不符 | 統一 `_publish_frame()`,失敗即丟棄該幀 |

### 階段 1 — 三項使用者功能

1. **Auto 對比鍵**:一鍵取整張畫面 1~99 百分位做線性拉伸(僅顯示,量測仍用原始灰階)。
2. **自動 ROI 免輸入尺寸**:偵測到樣本大小後,ROI 自動取樣本 65% 並置中(不碰邊);另加「≤ 0.9× 最近鄰距」夾限避免相鄰 ROI 重疊。
3. **De-glint 去亮反光**:取代難調的 threshold,自動去除白色灰塵/反光。

### 階段 2 — De-glint 方法演進(重點)

去反光的方法經過三次迭代,每次都由實測結果驅動:

**(a) 每個 ROI 內做 MAD 離群去除**
在 ROI 內丟掉「明顯比中位數亮」的像素。ROI 壓在樣本上時中位數=樣本亮度,只去掉真反光小點。

- 實測(ROI 置中壓在樣本上):

| 影像 | ROI 內去除(平均/最高) | 均值下降(平均/最高) |
|---|---|---|
| 20260811.jpg | 1.45% / 13.89% | 0.36 / 7.41 |
| 20260815.jpg | 4.74% / 19.44% | 2.48 / 14.01 |
| image.png | 2.14% / 5.56% | 0.30 / 0.65 |

**(b) 預覽改「整張圖」→ 暴露全域 MAD 的缺陷**
使用者希望預覽視窗看整張圖。改成對整張影像做**全域** MAD 後發現問題:最亮的樣本本體遠高於全域中位數,被當成離群**整塊挖黑**(20260815 去除量暴增到 4~15%,樣本 1、2 全黑)。
→ 結論:灰塵/雜訊的本質是**小面積亮點**,不是「比背景亮的大片區域」。全域亮度門檻不適用。

**(c) 改用 White Top-hat(頂帽)—— 最終方法**
先形態學 opening 抹掉大片亮區(樣本本體),殘留的只有小亮點(灰塵/反光),再對殘留門檻化。

- 實測:20260815.jpg 去除量從 4~15% 降到 **0.64%**,樣本本體完整保留,只去掉樣本邊緣小反光、右下角亮團、左上角與底部亮帶 —— 正是肉眼認定的雜訊處。

### 階段 3 — 去除後「填補」而非「留黑」

使用者提出:被點掉的黑洞換成與鄰近樣本相似的像素。改用 `cv2.inpaint`(Telea)從鄰域填補,預覽與量測皆套用。

- 實測(整張圖,填補 vs 排除的平均值):

| 影像 | 去除量 | 平均值:排除 vs 填補(差) |
|---|---|---|
| 20260815.jpg | 0.64% | 42.22 vs 42.53(0.31) |
| 20260811.jpg | 0.87% | 7.65 vs 7.71(0.06) |

→ **平均值幾乎不變**;填補的價值在於視覺乾淨與樣本內部空間標準差降低。

### 預覽視窗形式

- 整張未處理影像、**單一畫面三張並排**:原圖 / 去除後(填補)/ 去掉的反光(紅)。
- 勾選 De-glint 即彈出,亦可按「預覽去除效果」重開。

## 二、用到的技術原理

### 1. 百分位線性對比拉伸(Auto 對比)
取影像的 1、99 百分位為 `[lo, hi]`,線性映射到 `[0, 255]`:
`out = clip((gray − lo) × 255 / (hi − lo), 0, 255)`。
百分位(而非 min/max)可抵抗極端亮/暗離群點,對「亮點+暗背景」穩定。僅作用於顯示。

### 2. 自動框選:連通元件 + k-means + 樣本尺寸推導
- 背景平坦化(高斯)→ Otsu 二值化 → 連通元件取亮點質心與面積。
- 質心用 1D k-means 分群成 R 列 × C 行的網格座標。
- 由亮點面積推回等效直徑 `d ≈ 2√(面積/π)`,ROI 取 `0.65·d`,自然落在樣本中心不碰邊。

### 3. 穩健統計:中位數 / MAD
MAD(中位數絕對偏差)= `median(|x − median(x)|)`,`1.4826·MAD` 近似穩健標準差。相較平均/標準差,不被少數極亮反光像素帶偏。用於早期 de-glint 與門檻推估。

### 4. White Top-hat(形態學頂帽)—— 最終去反光核心
`tophat = gray − opening(gray, kernel)`。
- opening 會抹掉「比 kernel 大」的亮結構(樣本本體)→ 其 tophat ≈ 0,**被保留**。
- 「比 kernel 小」的亮點(灰塵/反光)在 opening 後消失,tophat 殘留高值 → **被偵測**。
- 門檻:`tophat > mean + K·std`,挑出小面積亮斑。
- 兩個校正旋鈕:`DEGLINT_KERNEL`(需大於灰塵、小於樣本)、`DEGLINT_K`(嚴格度)。

### 5. Inpaint 填補
`cv2.inpaint(gray, mask, radius, INPAINT_TELEA)`:用遮罩邊界向內傳播鄰域資訊,把反光像素補成與周圍樣本相似的值,避免黑洞。

### 6. 量測完整性相關
- **Deadline 配速**:`next_due += 1/fps`,使保留幀在整秒內均勻分佈,避免對週期性光源相位混疊。
- **Frame 序號同步**:`frame_seq` 每發布一張 +1,分析迴圈只在序號改變時取樣,確保每幀計入一次。
- **執行緒安全**:所有 Tk 更新以 `root.after(0, …)` 丟回主執行緒(Tcl 非執行緒安全)。

## 三、為什麼這麼做(設計理由與取捨)

1. **先修量測完整性,再加功能**:功能做得再好,若底層每秒平均本身有相位混疊或重複計數,數據就不可信。前 6 項是地基。

2. **顯示與量測分離**:Auto 對比、灰階拉伸只改「看到的畫面」,量測一律用原始灰階 —— 讓操作者能看清楚,又不影響數值。

3. **De-glint 為何最終選 top-hat 而非亮度門檻/MAD**:
   - 亮度門檻(threshold)與全域 MAD 都以「亮度絕對值」判定,會誤把整片亮的樣本當雜訊。
   - 灰塵/反光的判別特徵是**空間尺度小**,不是**亮**。Top-hat 正是「依尺度」而非「依亮度」的濾除,能保留大片亮樣本、只去小亮斑。實測從 4~15% 誤除降到 0.64%,直接驗證。

4. **為何改「填補」而非「留黑」**:
   - 對**平均值**:填補值≈樣本平均,與排除算出的平均幾乎相同(實測差 <0.31 灰階),對 CSV 數值與時間 CV 影響可忽略。
   - 對**視覺與空間均勻度**:填補讓樣本內部無孔、空間標準差下降,操作者判讀更直覺。
   - 取捨:填補會插入合成像素;但因平均值不變,唯一影響是「ROI 內空間 std」,而該值目前未寫入 CSV,故無誤導風險。

5. **保留校正旋鈕(而非寫死)**:真實光學/樣本大小會變,`DEGLINT_KERNEL`、`DEGLINT_K`、`K=0.65` 尺寸比例都留成常數可調,而非硬編一個「看起來剛好」的值。

6. **每次改動都用真實影像量化驗證**:每個方法都在 `20260811.jpg / 20260815.jpg / image.png` 上跑數字+視覺對照,而非靠肉眼直覺 —— 全域 MAD 的缺陷就是這樣被抓出來的。
